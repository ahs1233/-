# معمارية المنتج — تجربة الرئيسية وبنية التنقّل (المرحلة 0)

> **الحالة:** معتمدة كأساس للتنفيذ · **النوع:** معمارية منتج (Product Architecture / IA)، وليست كوداً ولا تصميماً هندسياً.
> هذه الوثيقة تسبق كل كود. Discovery يُنفَّذ **ليخدم هذه التجربة**، لا العكس. مرجعها: `domain-map.md`.

---

## 0. لماذا هذه المرحلة قبل الكود

المعمارية أصبحت صحيحة، لكن **أول ما يراه المستخدم عند فتح التطبيق ما زال يعكس «متجر إلكتروني»، لا «السوق العراقي».** الصفحة الرئيسية **هي هوية المشروع**. لذا نُثبّت التجربة أولاً، فيُبنى المحرّك على مقاسها — بدل بناء طبقة تقنية ممتازة نكتشف لاحقاً أنها لا تعكس الهوية.

---

## 1. عقد أول ٥ ثوانٍ

عند فتح التطبيق، خلال ٥ ثوانٍ، يجب أن **يرى** ويُدرك ويشعر:

| يرى | يُدرك | يشعر |
|---|---|---|
| اسم محافظته + «شنو الجديد اليوم في بغداد؟» | «هذا مبنيّ حول مكاني أنا» | ألفة |
| **متاجر وبيجات** (لا شبكة منتجات) | «هؤلاء جهات حقيقية أعرف بعضها» | ثقة |
| شارات توثيق، تقييمات، «جديد هذا الأسبوع» | «هذا سوق حيّ، ليس كتالوج» | فضول |

الجملة التي نريد أن يقولها: **«هذا ليس متجراً إلكترونياً… هذا هو السوق العراقي.»**

---

## 2. المبدأ: الرئيسية جهاتٌ أولاً، عروضٌ نتيجةً

الكيان الأساسي = **CommerceEntity** (متجر فعلي | صفحة موثّقة | لاحقاً مطعم/صيدلية/…). المنتج **نتيجة** يُرى داخل الجهة، لا بطلاً في الأعلى.
التسلسل: `Governorate → CommerceEntity → Offer → Product` (انظر `domain-map.md §0.1`).

---

## 3. نموذج التنقّل (Navigation IA)

**النموذج الذهني:** *ادخل السوق (الرئيسية) → تصفّح الجهات → ادخل جهة (هويتها + عروضها) → عرضاً → اشترِ.*
المنتج يُبلَغ **عبر الجهة** أساساً، ثم مباشرةً عبر أقسام الاكتشاف (جديد/ترند) ثانياً.

**الوجهات الأساسية (شريط سفلي، ٥):**

| التبويب | دوره | سطح Discovery؟ |
|---|---|---|
| 🏠 **السوق** | مدخل السوق — الرئيسية المُنسّقة | نعم |
| 🗺️ **استكشف** | الخريطة: بالمحافظة / بالفئة / بنوع النشاط / **بالسوق** *(لاحقاً)* | نعم |
| 🔎 **بحث** | بحث موحّد (جهات + عروض) | نعم (سطح من Discovery) |
| 🛒 **السلة / طلباتي** | نواة الشراء | **لا** (سطح معاملات) |
| 👤 **حسابي** | الهوية | لا |

**سطحان محوريّان يجب فصل دوريهما بوضوح:**
- **صفحة الجهة (Entity Page)** = الوجهة. هنا «خل أشوف شنو نزل عند متجر فلان»: قصّة الهوية + التوثيق + التقييم + المتابعة + **عروضها**.
- **صفحة العرض (Offer/Product Page)** = التفصيل: العرض + الجهة التي تقدّمه + ثقتها + الشراء.

## 4. تشريح الرئيسية — الأقسام وترتيبها

الترتيب يعكس **هرم الانتباه**: جهات ← بيجات ← عروض ← خرائط تصفّح.

| # | القسم | يعرض | نوع `DiscoveryItem` | السؤال الذي يجيبه |
|---|---|---|---|---|
| 1 | **Hero** «شنو الجديد اليوم في محافظتك؟» | سياق المحافظة (مبدّل) + نبض | — | «أين أنا، وما الجديد؟» |
| 2 | 🏪 **متاجر محافظتك** | CommerceEntity (بطاقات كبيرة) | `entity` | «مَن حولي؟» |
| 3 | 📱 **بيجات موثّقة** | CommerceEntity (`kind=OnlinePage`, موثّقة) | `entity` | «بمن أثق أونلاين؟» |
| 4 | ✨ **اكتشف الجديد** | عروض وصلت حديثاً — *هنا تبدأ المنتجات* | `offer` | «شنو نزل؟» |
| 5 | 🔥 **ترند محافظتك** | عروض رائجة (مبيعات ٧ أيام) | `offer` | «شنو ينتشر؟» |
| 6 | ⭐ **متاجر تستحق المتابعة** | CommerceEntity (بالثقة) | `entity` | «مَن أتابع؟» |
| 7 | 🗺️ **تصفّح حسب المحافظة** | بغداد/النجف/البصرة/كربلاء… | تنقّل | «أرني محافظة أخرى» |
| 8 | 🏬 **تصفّح حسب الفئة/النشاط** | ملابس/أجهزة/… + مطاعم/صيدليات… | تنقّل | «أرني نوعاً معيّناً» |

**مخطّط سلكي (جوال، RTL):**

```
┌───────────────────────────────┐
│ 📍 بغداد ▾     السوگ        🔔 │  Hero: مبدّل المحافظة + نبض
│ «شنو الجديد اليوم في بغداد؟»    │
├───────────────────────────────┤
│ 🏪 متاجر بغداد              →  │  Tier 1 — بطاقات كيانات كبيرة (تمرير أفقي)
│ [■ بطاقة كبيرة ][■][■] …        │
├───────────────────────────────┤
│ 📱 بيجات موثّقة ✔           →  │  Tier 2 — صفحات موثّقة
│ [■][■][■] …                     │
├───────────────────────────────┤
│ ✨ اكتشف الجديد             →  │  Tier 3 — تبدأ العروض
│ [منتج][منتج][منتج] …            │
├───────────────────────────────┤
│ 🔥 ترند بغداد               →  │
│ ⭐ متاجر تستحق المتابعة      →  │
├───────────────────────────────┤
│ 🗺️ تصفّح حسب المحافظة          │
│ [بغداد][النجف][البصرة][كربلاء]  │
│ 🏬 تصفّح حسب الفئة/النشاط        │
├───────────────────────────────┤
│ 🏠 السوق  🗺️ استكشف  🔎  🛒  👤 │  شريط سفلي
└───────────────────────────────┘
```

## 5. بطاقة الهوية التجارية (Commercial Identity Card) — العنصر البطل

المستخدم لا يرى «Commerce Entity»، بل يرى **«مكاناً يثق به»**. لذا البطاقة ليست عرض بيانات، بل **هوية تجارية**: حقائق الجهة (Catalog) + تركيب الثقة (Trust). هي **أهمّ عنصر بصري في المشروع**؛ بطاقة المنتج ثانوية.

```
┌────────────────────────────────┐
│      [ صورة الواجهة/البانر ]      │
│ 🖼  اسم المتجر            ✔ موثّق │   الاسم + التوثيق
│ ⭐ 4.8 (120)  · 🏪 متجر فعلي · مطاعم│   تقييم · نوع الجهة · نوع النشاط
│ 🕐 منذ ٨ سنوات · 📦 سُلّم ١٢٠٠ مرة  │   العمر · الطلبات المُسلّمة  ← هوية
│ ⚡ يردّ خلال ساعة · إلغاء منخفض     │   سرعة الردّ · معدّل الإلغاء   ← ثقة
│ 👍 يوصي به المشترون               │   توصية                       ← ثقة
│ 📍 بغداد — الكرادة · 🆕 6 هذا الأسبوع│   الموقع · جديد هذا الأسبوع
│                       [ متابعة ]  │   متابعة (لاحقاً)
└────────────────────────────────┘
```

**بنية البطاقة:** الأسطر ٣–٥ (هوية/ثقة) هي ما يميّز السوگ عن أي كتالوج. **«جديد هذا الأسبوع»** مُشتقّ (عروض آخر ٧ أيام). نبدأ بالمتاح اليوم (اسم/تقييم/توثيق/نوع/عدد عروض/موقع) ونُضيف إشارات الهوية تدريجياً (المرحلة C). القصّة الكاملة (صور المحل، ساعات العمل، مَن يديره، وسائل التواصل) تعيش في **صفحة الجهة** — والبطاقة نافذتها.

## 6. القرارات المثبّتة قبل الكود

1. **الكيان الأساسي = CommerceEntity** (رئيسية جهاتٌ أولاً، عروضٌ نتيجة).
2. **ترتيب أقسام الرئيسية** كما في §4 (جهات ← بيجات ← عروض ← خرائط).
3. **نموذج التنقّل** = ٥ وجهات؛ النموذج الذهني «ادخل السوق → جهة → عرض».
4. **المحافظة = سياق كامل (Context)، لا فلتر** — لكلٍّ اكتشافها وترندها وأسواقها ومناسباتها وهويتها البصرية (المبدّل في الـHero يُعيد بناء السياق كلّه). *(البيانات الآن؛ الثيم لاحقاً.)*
5. **البطل = بطاقة الهوية التجارية (Commercial Identity Card)**؛ بطاقة المنتج ثانوية.
6. **`Offer` هو العقد، و`Product` نوعٌ منه** (يحمي دخول مطاعم/ورش لاحقاً).
7. **`Marketplace` (سوق) طبقة محجوزة** بين المحافظة والجهة (الشورجة/الحويش/العشار…) — تظهر لاحقاً كبُعد تصفّح في «استكشف» وكسياق للجهة؛ **لا تُنفَّذ في A/B**.

## 7. كيف تخدم المراحل هذه الوثيقة

| المرحلة | تخدم هذه الوثيقة بـ |
|---|---|
| **A — `DiscoveryItem` العام** | مُغلّف يجعل الجهات والبيجات والعروض تُرتّب في أقسام §4 نفسها (بلا if/else لكل نوع) |
| **B — إعادة بناء الرئيسية** | تنفيذ §4 و§5 بالضبط، متّصلاً بـ`discovery.home` المُعمّم |
| **C — هوية الكيان التجاري** | التوثيق/النوع/النشاط + بطاقة §5 الغنية + صفحة الجهة (القصّة) |
| **D — البحث** | نتائج (جهات + عروض) عبر نفس المُغلّف والترتيب |

---

## 8. ما نؤجّله (محجوز لا مبنيّ)

أنواع عروض غير المنتج (خدمة/قائمة/إعلان) · أنواع كيانات غير (متجر/صفحة) · رسم المتابعة الاجتماعي · صفحة هوية الجهة الكاملة · الفيديو/الأسئلة. كلها **خانات نوع** في `DiscoveryItem`/`CommerceEntity`/`Offer` — تُضاف دون إعادة تصميم.

---

> **الخلاصة:** الرئيسية تعرض **السوق** لا **الكتالوج**. جهاتٌ موثوقة في محافظتك أولاً، ثم ما تعرضه. هذه هي هوية السوگ — والكود يخدمها.
